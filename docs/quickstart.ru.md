# Артель: быстрый старт

Как поставить «ИИ артель Плотникова» на свою машину и подключить к ней проект, который уже в работе.
Пример — эталонная установка автора (Claude Code + Codex, оркестратор Orca, GitHub).

## 1. Установка (один раз на машину)

```bash
git clone https://github.com/mikeplotnikov/artel
artel/bin/install.sh
```

Скрипт копирует десять скиллов `artel*` в `~/.claude/skills`, синхронизирует их в Codex (если установлен инструмент синка, см. `docs/adapters/codex.md`) и записывает
путь к репозиторию в `~/.artel/repo`. Повторяйте его после каждого обновления артели. Чужие папки он не
трогает: заменяет только те, что поставил сам (в них лежит файл `.artel-installed`).

Личная конфигурация — `~/.artel/artel.toml` (образец: `artel.toml.example`). В ней провайдеры,
модели по классам, логин бота агентов. Проверка — матрица «роль → модель»:

```bash
python3 ~/.claude/skills/artel/scripts/matrix.py
```

## 2. Подключение проекта, который уже в работе (маршрут O)

1. Откройте проект в Orca и запустите новую сессию Claude Code в основной папке проекта. Модель —
   Opus 5.5 (`/model`), усилие high: при подключении проекта координатор работает на флагмане.
2. Напишите: **«Запусти артель: подключи этот проект»** (или `/artel`).
3. Дальше артель ведёт сама, по шагам:
   - **O0 — вопросы о проекте (≈10 минут вашего времени).** Что за проект, что сейчас в работе, куда
     нельзя лезть, какие папки агентам не читать, какие операции на проде агенты делают сегодня и
     какие из них оставить.
   - **O1 — снимок.** Скрипт без модели и без изменений в проекте; по нему артель предложит профиль
     (light / standard / critical).
   - **O2 — чтение проекта** агентами, в пределах разрешённых путей, и базовая линия тестов: прогон
     набора три раза, чтобы потом отличать старые падения от новых.
   - **O2a — отчёт о состоянии.** Одна страница: что работает в проде, что сделано и не выкачено, что
     в работе, что впереди по планам, где документы расходятся с фактами. Затем вопросы на
     подтверждение пачками по 3–4.
   - **O2b — пересмотр плана.** Каждый пункт прежнего плана получает вердикт «оставить /
     скорректировать / добавить / закрыть» с причиной. Отдельным списком идёт то, чего требует сама
     артель.
   - **Единственный гейт.** Одно окно «Needs You» в Orca: вы утверждаете состояние, профиль,
     пересмотренный план, судьбу незавершённой работы, защиту и миграцию документов.
   - **После гейта:** сначала переключение настроек (`.artel/project.toml`, блок артели в
     `CLAUDE.md`, `AGENTS.md`, коммит в `dev`), затем проверка защиты (`artel-doctor`): найденный
     секрет останавливает работу, настройки GitHub уходят вам, остальное становится задачами. Дальше —
     разбор незавершённой работы, перенос документов, финальная сверка и первые небольшие задачи.

**До гейта в проекте ничего не меняется**: ни код, ни настройки, ни ветки, ни документы. Прогресс
пишется в `work/onboarding/STATE.md`. Если сессия оборвалась, повторите ту же фразу, и артель
продолжит с записанного шага.

## 3. Работа после подключения

| Что нужно | Что написать | Что будет |
|---|---|---|
| Фича или баг | «Сделай …» / «Исправь …» | маршрут B: уровень риска, спецификация (кроме T0), приёмочные тесты до кода, реализация, две волны ревью другой семьёй моделей, merge в `dev` |
| Выкатить в прод | — | агент открывает PR `dev → main` с описанием и планом отката и спрашивает вас в чате; после «да» сам сливает и выкатывает. Среда агента (Claude Code, Codex) останавливает слияние, выкатку и перезапуски до вашего ответа — в Orca это «Needs You» |
| Прод упал | «Прод упал: …» | маршрут I в любом состоянии проекта, даже посреди подключения: сначала откат (если механизм есть и прод не стоит уже на последнем проверенном релизе), потом исправление |
| Найти проблемы | «Проведи аудит …» | таблица пробелов, вы выбираете, что чинить |
| Где мы | «Что дальше по проекту?» | ответ по `work/*/STATE.md`, без изменений |

Вопросы к вам приходят в Orca как «Needs You» и пушем на телефон. Остальное агенты делают сами:
коммиты и push в `dev`, деплой на dev/stage. Слияние в `main`, выкатка на прод и перезапуски — только
после вашего «да» в чате; это держит среда агента, а прямой push в `main` и PR без зелёных проверок
не пропустит GitHub.

## 4. Проверка защиты в любой момент

```bash
cd <проект> && python3 ~/.claude/skills/artel-doctor/scripts/doctor.py
```

FAIL — это то, что надо исправить до автономной работы, WARN попадает в план, MANUAL — то, что
скрипт сам доказать не может (живая проба защиты, персональные данные, механизм отката); такие пункты
проверяют руками раз на каждое изменение настроек. PASS ставится только там, где данные это
показывают.
